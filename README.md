# Cash Flow Forecaster

A web app for small businesses that turns a bank transaction export into a **13-week cash
flow forecast**. It shows when cash might run low, lets owners test what-if scenarios, and
checks its own accuracy against recent history.

Try it with the built-in sample data: 18 months of made-up transactions for a fictional
bakery, so no real financial data is needed.

## What it does
- **Upload a CSV** from a bank or accounting tool. It understands one signed Amount column
  or separate Debit/Credit columns, and money written as `$1,234.50` or `(85.00)`.
- **Sorts transactions into categories** (payroll, rent, supplies, taxes, card sales...).
- **Finds recurring payments** such as rent, payroll every 2 weeks, weekly suppliers, loans
  and subscriptions, by looking for the same payee at a steady interval and amount.
- **Forecasts the next 13 weeks** week by week, with:
  - recurring payments placed on their expected dates
  - everything else based on a typical recent week (the median of the last 12 weeks)
  - seasonality from last year when there is a year of history (sales, and supply costs
    that rise with sales)
  - tax payments expected on the same dates as last year (US estimated taxes don't fall
    at even intervals)
  - a rough 80% range based on how much weekly cash has varied
- **Low-balance alert** for the first week cash is projected to drop below a chosen level.
- **What-if scenarios:** revenue up or down by a percentage, a one-time expense in a chosen
  week, or a new monthly cost such as a hire.
- **Accuracy check (backtest):** forecasts the most recent 13 weeks using only earlier data
  and compares with what actually happened.
- Charts, a spending-by-category breakdown, and a CSV download of the forecast.
- User accounts with hashed passwords, CSRF protection, and per-user data in SQLite.

## Results on the sample data
| | |
|---|---|
| Recurring payments found | 11 (payroll, rent, suppliers, loan, utilities, insurance...) plus quarterly taxes |
| Backtest average weekly error | **$1,244**, vs. $7,093 for a simple "average week" guess (**82.5% better**) |
| Backtest 13-week total | over by $5,198 (too optimistic), because there wasn't yet a full year of history to learn the summer-to-fall slowdown |

## Tech
Python, Flask, SQLite, pandas, NumPy, matplotlib, pytest, Docker, GitHub Actions

## Run locally
```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Open http://127.0.0.1:5001, create an account, and click **Use sample data**.
(Port 5001 avoids macOS AirPlay, which uses port 5000.)

## Tests and lint
```
pip install -r requirements-dev.txt
flake8 .
pytest
```
23 tests cover CSV formats, categorization, recurring-payment detection, the balance math,
scenarios, the backtest, login, uploads, and users not being able to see each other's data.

## CI/CD pipeline (.github/workflows/ci.yml)
| Job | Runs on | What it does |
|---|---|---|
| **test** | every push and pull request | flake8 and pytest on Python 3.11 and 3.12 |
| **docker** | after tests pass | builds the Docker image, starts it, and checks `/health` |
| **deploy** | pushes to `main`, after the other jobs pass | calls the Render deploy hook |

To deploy on Render: create a Docker Web Service from this repo, set `SECRET_KEY` and
`COOKIE_SECURE=1`, add a persistent disk at `/app/instance`, and add the service's deploy hook
URL as a GitHub Actions secret named `RENDER_DEPLOY_HOOK_URL`.

## Sample data
`sample_data/sunrise_bakery_transactions.csv` is generated by `generate_sample_data.py`.
Sunrise Bakery is fictional; the file contains no real business's data.

## Limitations
- Estimates for planning only, based on past transactions. Not financial, tax or accounting
  advice.
- Needs at least 8 weeks of history; seasonality needs about 18 months.
- Doesn't know about future events that aren't in the history (a new contract, a price rise).
  The what-if scenarios are the way to add them.
- Real bank exports vary; unusual formats may need a new column name added to the parser.

## Privacy
Never commit real bank exports to a public repo. Uploaded data is stored only in the app's
database, under the user's account.
